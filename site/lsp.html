LSP

Code intelligence / LSP

.kiro/settings/lsp.json configures optional language servers for enhanced code intelligence (find references, go to definition, rename, diagnostics, hover) on top of the built-in tree-sitter support. Each language server needs to be installed separately and available on PATH.

Configured languages

TypeScript / JavaScript

typescript-language-server · .ts, .js, .tsx, .jsx

Python

pyright (via pyright-langserver) · .py

Kotlin

kotlin-language-server · .kt, .kts

Swift

sourcekit-lsp (via xcrun) · .swift

Smithy

smithy-language-server · .smithy

Each entry also defines project_patterns (files that signal a project root, e.g. package.json, pyproject.toml) and exclude_patterns (directories to skip, e.g. node_modules, __pycache__).

Getting started

Install whichever language server(s) you need and ensure they're on PATH, then run /code init to detect and start them. Use /code status or /code logs afterward to check on them.

Config excerpt

{
  "languages": {
    "typescript": {
      "name": "typescript-language-server",
      "command": "typescript-language-server",
      "args": ["--stdio"],
      "file_extensions": ["ts", "js", "tsx", "jsx"],
      "project_patterns": ["package.json", "tsconfig.json"]
    },
    "python": {
      "name": "pyright",
      "command": "pyright-langserver",
      "args": ["--stdio"],
      "file_extensions": ["py"],
      "project_patterns": ["pyproject.toml", "setup.py", "requirements.txt"]
    }
    // ...kotlin, swift, smithy
  }
}
